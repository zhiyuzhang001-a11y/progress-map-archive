# 运行、数据保全与维护边界

Codex负责本轮所有技术操作，不把启动、命令、备份或恢复验证转交用户。

## 启动与诊断

Start.command调用scripts/manage-service.ts start --open，按需独立启动Node进程并打开页面。service-data存私有运行日志，不保存会话token或安装全局服务。status从页面取得临时会话，再核对rootFingerprint、projectId、配置kind/dataDirectory及本地状态代次，不能把同身份外来副本误认成本项目。stop只关闭核对成功的本项目服务，关闭会等待已受理写入完成。终端退出不会停止该独立进程；机器重启后重新按需启动。

重复启动复用已有服务。端口被外来服务占用时失败，不杀进程。浏览器打开失败时服务继续就绪，返回URL；本轮实际打开检查与浏览器失败注入分开记录。普通页面关闭不会停止服务，显式关闭后页面停止刷新；Codex负责重启再交付。

## 完整保全与受控隔离

node backend/cli.ts export --destination 新目录导出binding、state、存在的previous、快照、视图、隔离文件和显式配置；verify-export --destination 目录校验必需文件、路径、重复项、逐项字节摘要、状态内部摘要、身份、根目录来源、revision及代次。导出不释放容量，不删除源数据。导出包本身不是任意根目录可直接启动的项目，binding仍保留原规范化根目录。

v0.5导出包version2还包含状态中的固定历史结项、证据登记清单以及当前、previous和快照所引用的必要证据内容文件；快照的证据副本随包保全。verify-export核对引用依赖与摘要，clone创建合法隔离绑定并复制证据。读取兼容旧version1包，但旧包只覆盖其实际内容，不能宣称其未收录的evidence目录可恢复。v0.4源程序、数据及完整原证据另保全于archives/v04-before-v05-full.tar.gz，隔离解包102份证据摘要已核对。

backup返回evidenceCoverage=registered-records-only：只承诺登记清单中的内容，不是整个文件系统备份。历史结项及必要记录先登记，再建立含文件的快照。恢复前验证快照依赖文件，缺失或摘要不符拒绝；可由完整快照补齐当前缺失内容。旧快照没有登记清单时明确其覆盖边界。主项目仍仅备份与导出，实际恢复仅在受控隔离副本。

证据由register-evidence有限报告动作登记，绑定原基线、候选、证据与成果版本；源路径只限本项目evidence目录，验证路径、符号链接、内容摘要、大小和类型后安全保存内容副本。页面与CLI按登记id+成果版本只读访问（CLI：evidence-record --record id --version version）。读取不接受任意路径，不执行命令、HTML或脚本，不自动加载外部资源。

clone --destination 已存在空目录是受控隔离复制入口，核对来源摘要，保留clone-origin完整原包与清单，创建同项目身份的新根目录绑定和新recoveryEpoch。业务意见、回应、验收/撤回、候选、证据和历史保全；隔离活动回执为空，来源原回执保留于clone-origin，旧代次请求在回执查找前拒绝。目标配置不依赖缺失的初始种子文件。实际测试副本单独复制当前代码/dist后启动，测试中的用户动作标注模拟，不写进真实主状态。

禁止手改binding、integrity或恢复代次来启动复制的文件夹。未知未来schema拒写；原schema1模拟来源不能更名为真实来源。已有目录缺失绑定或损坏不会自动重建为新样本。

## 本轮恢复验证

真实主状态只备份/导出，不做破坏性回退。受控副本中保留原聊天意见并执行明确标注的模拟用户验收和撤回，建立快照，然后验证CLI与网页同revision竞争、离线服务关闭期间CLI恢复、重启后旧网页session与请求、旧CLI已提交回执重放拒绝。恢复前后来源及意见/验收/撤回保全，主项目字节不变。实际日志为evidence/v04-recovery-real-tests.txt。

执行恢复前，Codex读取recovery-preview确认回退范围及expectedFileHash；make-request为restore动作生成新鲜上下文，再recover --confirm-loss。恢复创建新代次，旧页面必须重载；不将旧草稿自动换代次提交。服务器视图也核对代次，旧位置不能在恢复后自动带入。

## 演示回退与容量

默认真实配置和演示配置分开。需要查看演示时只显式--config demo.config.json，端口4174，不覆盖project.config.json或真实状态。完整旧运行版本保留archives/demo-v1-20261011；其binding指向原根目录，因此不是直接从archive子目录启动，更不能作为真实项目backup恢复。需要回退代码时先导出主状态并由Codex准备受控版本切换，不能以拷贝模拟state覆盖真实state。

页面容量提示包括2MB状态文件、2000历史/幂等回执、32快照，以及节点、验收条件、自动规则、节点报告、候选、证据、轮次、意见、已读、回应、决定、优先级、提案和基线历史各自上限。达到限制停止相关写入；仅导出不回收容量。没有实现安全业务压缩，不承诺无限使用。快照迁出须先核对独立副本，本轮没有删除仍被引用事实或自动清理功能；需要业务容量回收时另行审核引用保全、幂等及代次方案。

## v0.7 展示与维护保护

用户首页从权威事实派生四个成果分计划，不建立可单独编辑的第二份项目状态。地图核对点位于 state.mapCheckpoints，由受控 map-checkpoint 动作从当时记录生成； report、页面打开和刷新不重设比较点。点包含项目、范围、修订、恢复代次、来源完整性摘要和可核对事实。最多100个点，统一2MB状态文件上限；容量接近上限要明确归档保全，不自动删旧点。

新范围启用固定原待验收候选及证据引用；原B2六项保留在原范围，历史受控通过/退回合法引用原链并记录原话，旧结项快照仍表达当时状态。普通CLI无历史验收权限。回退程序或恢复资料前核对当前修订及代次，期间新决定须保全，不能旧副本覆盖；主项目不做破坏性恢复。

地图比较点、原候选/证据引用和两类视角均随既有完整导出携带。恢复或克隆后旧比较点需重新核对，旧网页/CLI请求不可重放。显式重新核对只增加一个有依据的新点，不移除旧点。

view.json 内新增 mapV7 槽位保存新版地图位置、展开、视角与窗口尺寸；内部旧视角仍使用原位置/折叠字段。两种更新均在Store锁内合并，不相互覆盖，合并后仍受100KB视角上限。视角不是进展事实。恢复代次不同或只读备份时不套用旧视角，前端按当前内容重新布局；只读配置及只读备份禁止视角写入。
