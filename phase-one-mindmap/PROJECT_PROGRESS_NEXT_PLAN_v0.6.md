# 项目进度工具下一阶段计划 v0.6：只用思维导图看计划、进展和难题

日期：2026-10-12。

状态：待用户审核。本次只制定计划，不开始实施，不修改页面、程序、运行配置或项目状态。此前连续实施授权限于 v0.5，不自动启动本计划。

## 一、这次要解决什么

用户反馈：界面不够简单，看不到总计划、当前进度和难解决的问题；“易读证据与实际使用”“轮次与历史保全”等主分支让人无法理解这个项目到底在做什么。

用户进一步明确：思维导图是给用户看的，用户只关注总计划、分计划、进展、难题及完成情况。整个主页面只放思维导图，点击卡片出现详情；清除其他提示文字、按钮和零散区域，让页面整洁、简洁、有效率。GPT 需要的技术细节可以保留，但不进入用户主页面。

本计划据此替换原稿的“三块首页”布局。总计划、进度和难题都融入同一张导图，不另建顶部总览、进度面板或问题列表。

本次仍只管理这个项目自身。它的总目标用普通话表达为：**做一个打开就能看清项目计划、进度和难点，并方便你验收成果的工具。**

## 二、首页打开后应该看到什么

**默认主页面只有思维导图。** 没有独立页眉、介绍段落、操作提示、工具栏、搜索框、统计面板、历史切换、验收按钮、技术入口或常驻侧栏。项目名称与总目标在中心卡片中呈现，卡片和连线组成页面主体。加载、失败等实际异常仅在发生时简短呈现，不留下日常说明或把故障伪装成空白导图。

### 1. 总计划：要做到什么，分几步做

中心卡片显示项目名称和一句总目标，左右主分支按实际工作关系组织分计划。拟定的内容归纳如下，具体名称由阶段一核对后改成短而直接的成果名称：

- **能看计划**：用导图展示目标和任务，支持展开、折叠和查看任务。
- **能跟踪项目**：让页面反映这个项目的实际工作、成果和反馈。
- **能持续使用**：后续工作接得上，之前确认的成果仍可查看。
- **看得清、用得顺**：首页直接说明总计划、进度和难点。这是本次要改善的部分。

这些是对已有工作和本次拟做工作的归纳，不把它们写成四个新项目，也不把以往版本号作为主标题。实施前由 Codex 核对每一步对应的实际计划和成果：已完成、待验收、正在做和计划中分别标明；本计划未获准时，最后一步只能标为“计划中”。

总计划默认展开到主分计划，能看清层级、已完成的部分及当前工作。下级任务只在必要时展开，不把所有历史任务一次铺开。卡片名称说清要完成什么，不使用“易读证据与实际使用”“轮次与历史保全”等实施分类。

### 2. 当前进度：做到哪里了，还剩什么

进度直接体现在卡片和连线上：每张卡片只保留短标题、一个简短状态及必要的进度表达；通过统一的颜色、线条和文字区分完成情况，不依赖颜色才能理解。当前工作明确标记，首页不另放解释段落或数量面板。具体完成了什么、还差什么，点击卡片再看。

- “已完成”表示已有实际验收依据；工作做好但尚未验收，显示“待你验收”。
- “正在做”需要实际工作记录支持；计划写好了不等于正在实施。
- 一个任务只有一个主状态，受阻任务可另加简短难题标记，不在首页叠加一串标签。
- 能准确汇总时，分计划可在卡片内显示“已完成 x/y”，含义与详情一致；无法准确汇总时显示状态，不编造百分比。不能把本次尚未通过的工作用过去成果凑成完成。汇总依据留在详情及内部记录，不加首页说明。
- 过去完成的成果与本次待做事项都能在总计划中找到；详情中保留原来的验收记录，重新命名和分组不会改变旧决定。

### 3. 难解决的问题：卡在哪里，准备怎么办

难题附着在受影响的分计划或任务卡片上：用一个明确标记和必要的短问题名使它能被注意到；问题本身是需要独立处理的工作时，才作为关联任务展开。没有难题时不显示空问题区或“暂无问题”提示。点击相关卡片后回答：

- 卡在哪里？
- 影响哪一步或哪项成果？
- 下一步准备怎么处理？
- 是否需要你最后作决定？

普通待办不算难点；技术检查失败、缺少必要材料、反复未解决的问题或用户明确指出的问题，才依据记录列出。问题是否已核对及没有记录的情况放在详情说明，不在主页面反复提示，不把未记录当作没有问题。

本次已知问题就是“首页看不清总计划、进度和难点”，应保留用户反馈来源，在完成改进后标为“已改，待你确认”，不能由自测直接标成用户认可。其余难点由 Codex 核对现有记录，不为填满三项编造问题，不自动推断负责人、工期或逾期。

## 三、卡片详情与 GPT 所需记录

用户卡片使用任务名称和“已完成”“待验收”“进行中”“未开始”等简短状态。点击卡片才出现详情，内容限定为这项计划要完成什么、进展、难题、下一步及完成结果，使用普通语言。没有相关内容的栏目不占位。

详情默认收起，关闭后回到纯导图。点击卡片外区域或按 Escape 关闭；卡片点击打开详情，详情内点击分计划可展开对应分支，兼顾键盘操作。平移、缩放和折叠无需常驻工具栏或提示文字，具体交互由实施阶段验证，不把双击作为唯一操作方法。

GPT 所需的任务对应关系、检查日志、文件路径、成果版本、原始证据和验收记录继续通过现有内部数据及 CLI/API 使用。用户详情也不默认堆放这些技术内容；具体成果本身需要查看时，只呈现相关成果。隐藏是展示层级调整，不删除记录、不放宽读取权限、不另建后台或第二套数据。

移除主页面历史与验收入口，不等于删除已有功能和记录。用户仍可在聊天给出最终验收，由 Codex 按明确展示的范围和版本通过既有受控入口记录，不要求用户操作后台。内部历史查询、验收动作及保护继续保留并检查。页面上的结论必须对应真实记录，不能为简洁掩盖失败或未验收状态。

## 四、分三个阶段实施

### 阶段一：整理真正的总计划

Codex 核对最初计划、后续计划、已有成果、用户决定和当前待验收事项，把它们整理成第二节中的清楚步骤。为每个步骤建立与原任务、成果和决定的对应关系，并整理真实问题清单。

先形成纯导图内容稿和布局草图，明确中心、左右分计划、卡片状态、连线进度及难题标记；逐项决定旧页面内容从用户界面移除还是保留为内部记录，防止只是把杂乱内容挪进详情。当前资料表明 v0.4 已验收，v0.5 技术交付完成但六项尚未得到用户最终验收；实施时再次核对，不把新计划批准当作这六项通过。

独立 agent 检查：总计划是否覆盖整个项目、分组是否易懂、进度是否真实、是否漏掉用户指出的问题。发现问题先修复，再继续；不增加用户中途审稿义务。

### 阶段二：重新组织首页

实现以中心总计划、左右分计划组成的纯导图首页。清理页眉、介绍、操作提示、工具栏、面板、搜索、历史切换和验收入口等外围内容；默认没有侧栏。进展、难题和完成情况直接呈现在相应卡片及连线上，点击卡片出现简洁详情。

首页的任务状态、导图节点和详情使用同一份项目事实，避免三处说法不同。重新分组与改名只改变显示组织，不重写验收决定或丢失原记录。新计划获准后的任务单独标清，不覆盖 v0.5 待验收成果。

桌面初始视图完整呈现中心和主分计划，卡片不重叠，文字清楚，留白适当，不因删掉面板而留下空壳。手机默认仍为导图，通过紧凑布局与可收起的分支保留可读性，不用一屏塞满全部任务或换成仪表盘。保留连线进度、卡片详情与分支收展，检查触摸及键盘操作不依赖悬停或提示文字。历史查询、原验收功能从内部入口检查，不要求它们继续出现在用户首页。

独立 agent 从用户视角检查首屏、文字、导图层级、手机阅读和状态一致性，修复后继续。

### 阶段三：核对真实展示并交付

使用本项目真实记录核对首页。用隔离数据检查未开始、进行中、工作做好待验收、已验收、退回和卡住等情况，确认每种情况下都能说清楚总计划、进度与问题。

检查默认页面确实只有导图，无残留说明、按钮、空面板或隐藏侧栏占位；卡片详情默认收起，打开与关闭顺手，详情不变成技术日志列表。检查导图收展、平移缩放、成果查看及内部历史与验收动作仍可用，核对旧成果和决定没有因改版改变。按改动影响完成必要自测和备份检查；涉及保存内容或数据结构变化时，补做隔离恢复验证，沿用已有旧请求拒绝保护。

独立 agent 作最终复核，修复发现的问题。Codex 启动服务、确认桌面与手机页面可操作，并提供入口及简短验收说明。技术检查和独立审核不代替用户最终验收。

## 五、本次六项验收标准

1. **看得懂总目标**：首页能直接读到这个项目最终要做到什么。
2. **看得见总计划**：能看到主要步骤、前后关系和当前所在位置，内容不只围绕本次技术改动。
3. **看得清进展与完成情况**：卡片和连线清楚区分已完成、进行中、待验收和未开始，表达与记录一致，无需阅读旁边的说明面板。
4. **找得到难题**：受影响卡片有明确标记，点开能看到原因、影响和下一步；未记录不冒充一切正常。
5. **主页面干净，详情简洁**：默认只有思维导图，没有外围提示文字、按钮、工具栏或常驻面板；点击卡片出现面向用户的详情，技术细节不堆入详情。桌面与手机均可操作。
6. **内部记录完整**：原任务、成果、决定、历史查询和验收能力保留，GPT 能通过既有内部入口核对；新工作不自动通过，用户不用接触技术操作。

这些是本次新的六项，不替代或自动通过 v0.5 的六项。最终交付可把仍待验收的旧成果与本次改版一起提交，但须分清各自范围与结果，不能用一句通过追溯到未展示的内容。

## 六、用户只负责最后验收

你最后只需打开首页，看能否直接回答：

- 这个项目总共要做什么，现在走到哪一步？
- 哪些已经完成，哪些还在做，哪些等我验收？
- 最难解决的是什么，接下来打算怎么处理？

再点开一个任务，确认详细说明是否容易理解。你可以整体通过、部分通过或指出需要修改的地方；不要求运行命令、手工备份、整理项目记录或逐阶段审核。

Codex 负责内容核对、实现、启动、自测、备份、必要恢复验证、独立审核和交付。本计划获准实施后，三个阶段连续推进，每阶段审核修复，不中途增加用户操作负担；超出本计划范围的实质扩展另行提出。

## 七、这次不扩大的范围

复用现有程序，不新建一套后台，不接入其他项目、Atlas 或 PDF，不增加云端、账号、自动执行、实时 agent 监控或全局设置。问题展示依据已有记录及本次实施记录，不承诺自动发现所有阻碍。

只调整本工具的总计划表达、纯导图布局、卡片详情、进展与难题呈现，以及必要的兼容修正。删除用户界面的冗余区域，保留 GPT 所需内部记录，不增加容量清理、聊天监听或额外平台功能。
